# Final report — offer-diff

## Implemented scope

Builds exactly the brief in `TASK.md`: upload an original and a revised commercial offer
(PDF), get back the substantive changes (scope/quantities/unit prices/totals/delivery
dates), each referencing both source documents, plus arithmetic-discrepancy detection and
explicit decline-to-conclude behavior when the inputs fall outside the stated scope
(currency mismatch, or over the page/line-item limits).

Explicitly out of scope (per the brief, not attempted): OCR/scanned or handwritten PDFs,
multi-currency comparison, legal analysis, accounts, payments, multi-language input.

## Complete flow

1. Browser: user selects `original.pdf` and `revised.pdf`, clicks Compare.
2. `POST /api/compare` (multipart, two files) — `src/server.ts`.
3. `extractText()` (`src/pdf/extractText.ts`) — deterministic, per-page text extraction via
   `pdfjs-dist`, no OCR.
4. `StructuringProvider.structureOffer()` — turns raw text into a structured
   `{docTitle, currency, offerDate, deliveryDate, items[], printedGrandTotal, ...}` record,
   with a page+verbatim-snippet reference for every field. Real implementation used for
   measurement: `GeminiStructuringProvider` (Google Gemini, forced JSON output via
   `responseJsonSchema`); `ClaudeStructuringProvider` (Anthropic, forced tool-use) also
   implemented behind the same interface but not exercised with a real key.
5. `matchItems()` (`src/matching/matchItems.ts`) — deterministic, order-independent,
   rename-tolerant (token-Jaccard similarity) matching between original and revised line
   items. Exact / confirmed / uncertain confidence tiers.
6. `computeDiff()` (`src/diff/computeDiff.ts`) — deterministic: currency-mismatch decline
   check, per-matched-pair quantity/price comparison, removed/added items, date comparison
   (format-tolerant), independent recomputation of each document's total from its own line
   items compared against the printed total (arithmetic discrepancy, never silently
   corrected).
7. JSON response rendered by `public/app.js` into a concise, decision-oriented report:
   substantive changes table (with source references), arithmetic discrepancies, uncertain
   matches, or a decline banner.

## Difficult inputs tested

Test set: `test-set/input/{normal, ambiguity-reorder-badtotal, decline-currency-mismatch,
formatting-only}`, generated by `scripts/generateFixtures.ts` (deterministic, ground truth
recorded in each scenario's `ground-truth.json`, expected differences written to
`expected.md` before ever running the pipeline). Full expected-vs-actual comparison:
**`docs/test-report.md`**. Summary: **4/4 pass, with the real Gemini API** (not just the
mock fallback — see below).

- **normal**: quantity change, unit price change, item removed, delivery date changed — all
  4 detected, correctly referenced, no false positives.
- **correction/ambiguity** (renamed + reordered item, intentionally wrong printed total):
  item matched across rename+reorder (Jaccard similarity 0.75, correctly surfaced as an
  *uncertain* match rather than asserted with false confidence or split into a false
  removed+added pair); the real quantity change on that item was still correctly attributed
  to it; the wrong printed total was flagged as a 27.50 arithmetic discrepancy rather than
  silently trusted or silently "corrected."
- **clarification/decline** (currency mismatch, USD vs EUR): correctly declined to compare
  amounts instead of guessing.
- **formatting-only** (case, date format, thousands separators changed, nothing else): 0
  substantive changes reported, as required by the brief.

**Unplanned difficult input, encountered for real while capturing evidence screenshots:**
Gemini itself returned a genuine transient `503 UNAVAILABLE` ("model currently experiencing
high demand") on two calls, and the free tier's rate limits (5/min, 20/day — see
`docs/cost.md`) were hit for real during testing. The app surfaced both as visible errors
instead of crashing or hanging (see `docs/screenshots/05-real-daily-quota-exhausted.png`),
and retry-with-backoff was added directly in response to the 503s actually observed — not
speculatively. This is real evidence of "difficult input" handling that no synthetic fixture
would have produced.

## Usability notes

- Single-screen flow: two file pickers, one button, one report. No accounts, no multi-step
  wizard.
- The report leads with a decline/no-change banner when applicable, so a reviewer sees the
  bottom line first; the full change table is secondary.
- Every change row carries the literal source text it came from (page + snippet) so a human
  can verify a claim against the PDF in seconds, per the brief's "every change must
  reference both source locations" requirement.
- A visible banner explains when the mock parser (not real AI) produced the result, so a
  reviewer is never misled about what actually ran (and no such banner appears when the
  real Gemini API is configured and used).

## Measured performance

See **`docs/measurements.md`** for the full raw data. Two parts:
- **Deterministic pipeline** (extraction + matching + diff, mock structuring step), 10 runs
  + 1 warm-up: **avg 10.64 ms, min 6.97 ms, max 16.28 ms**. First-call cold start
  (pdfjs-dist init) observed once at **4844.8 ms**, paid once per server process.
- **Real AI structuring step (Gemini `gemini-2.5-flash`)**, 4 real comparisons (8 API
  calls) on 2026-09-10: structuring time **avg 7461.6 ms, min 4992.8 ms, max 9415.5 ms**
  per comparison (2 parallel calls). Sample limited to n=4 by the free tier's rate limit
  (5 requests/minute/model — confirmed directly from the API's own error, see
  `docs/cost.md`). **Time to a useful result** (warm process, extraction ~7-16ms + real AI
  call): roughly **5-9.4 seconds per comparison** in this sample.

## Reproduction instructions

```bash
git clone <this repo>
cd offer-diff
npm install
cp .env.example .env        # optionally set GEMINI_API_KEY (free tier) or ANTHROPIC_API_KEY
npm test                    # 9 unit tests
npx tsx scripts/generateFixtures.ts   # regenerate the 4 test-set fixtures (deterministic)
npx tsx scripts/runTestSet.ts         # run the full pipeline over all 4 scenarios
npx tsx scripts/runOneScenario.ts normal   # run a single scenario (useful under free-tier rate limits)
npx tsx scripts/measure.ts            # timing measurement (deterministic part)
npm run dev                 # http://localhost:3000
npx tsx scripts/browserCheck.ts       # drives the real browser UI (server must be running)
```
Note: with `GEMINI_API_KEY` set, `runTestSet.ts` may hit the free tier's 5-requests/minute
rate limit if run back-to-back with other AI calls — see `docs/cost.md` for the confirmed
limit and `runOneScenario.ts` as the workaround used in this submission.
All dependency versions are pinned in `package.json`/`package-lock.json`. `npm audit`
reports 0 vulnerabilities as of this submission.

## Tradeoffs

- **Decision:** use an LLM only for text-to-structured-JSON extraction, and keep matching,
  diffing, and arithmetic entirely in deterministic code.
  **Reason:** the brief requires "recalculate totals deterministically... do not silently
  replace what the source says" — arithmetic and identity decisions must be auditable and
  reproducible, which an LLM's own arithmetic is not.
  **Alternative considered:** ask the LLM to do the full comparison in one call.
  **Tradeoff:** more total LLM calls (2 structuring calls instead of 1 comparison call), but
  every number and every match decision is independently unit-testable without an API key.

- **Decision:** token-based Jaccard similarity for item matching, not full ML/embedding
  similarity.
  **Reason:** deterministic, dependency-light, testable, and transparent about *why* two
  items matched (shared tokens), which matters for a decision-support report a human must
  trust.
  **Alternative considered:** embedding-based semantic similarity (via an API call).
  **Tradeoff:** would handle synonyms ("Bolt" vs "Fastener") better, at the cost of another
  paid API call per item pair and much harder-to-audit "why did it match" reasoning.

- **Decision:** regex mock fallback when no API key is present, instead of blocking all
  progress on a funded key; later, adding Gemini as a second real provider (checked first)
  once a free-tier key became available, rather than waiting on the paid Anthropic key.
  **Reason:** the user could not immediately fund an Anthropic API key, but Google AI
  Studio offers a genuinely free tier; the brief allows "any AI tools, models."
  **Alternative considered:** wait for the Anthropic key and leave the AI step unmeasured.
  **Tradeoff:** real measurements exist for Gemini specifically, not Claude — the exact
  numbers in `docs/cost.md` would differ (likely be higher-cost, possibly different
  extraction quality) on Claude. The interface makes switching a config change, not a
  rewrite, so re-measuring on Claude later is low-effort if desired.

## Known limitations

- **Claude has not been exercised with real API calls** (only Gemini has, so far) —
  `ClaudeStructuringProvider` is implemented and type-checked but unverified at runtime.
- **The Gemini measurements are a small sample (n=4)**, limited by the free tier's rate
  limits — not a large-scale accuracy or latency study.
- **Free tier has two confirmed hard caps**, both discovered from real API errors while
  building this project: **5 requests/minute/model** and **20 requests/day/model** (see
  `docs/cost.md` §3.1 and `docs/screenshots/05-real-daily-quota-exhausted.png`). A fresh
  free key supports roughly 10 real comparisons/day — a real constraint for reproducing
  this project's measurements same-day, and for any real usage beyond a demo.
- **Retry/backoff is now implemented** (`src/ai/geminiProvider.ts`: 3 attempts, exponential
  backoff on 429/503) after real testing hit both a rate limit and a genuine transient `503`
  from Gemini ("model currently experiencing high demand"). It has not been tested against
  a paid tier's higher limits, only the free tier's.
- The regex mock (used only when no API key is configured) only understands this project's
  own fixed table layout; it will silently under-extract or fail on real-world offer PDFs
  with different formatting.
- Date parsing (in the deterministic diff engine, independent of the AI step) supports ISO
  (`YYYY-MM-DD`) and one long-form pattern (`Month D, YYYY`) only; other real-world date
  formats fall back to raw string comparison.
- No multi-currency support (by design, per scope) — mismatched currency triggers a decline
  rather than a conversion.
- Not deployed publicly; browser demo is local (`npm run dev`).
- Exact current Gemini and Anthropic API pricing not confirmed from either provider's own
  site (network egress restriction in this sandbox) — token counts are real measurements,
  but the dollar figures in `docs/cost.md` depend on unverified third-party prices.
